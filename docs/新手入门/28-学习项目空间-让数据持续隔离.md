# 28. 学习项目空间：让数据持续隔离

> 难度：入门到进阶
>
> 本章目标：把不同课程、方向或项目的学习记录分开保存，并理解 WebUI 如何在不丢失旧数据的前提下切换项目空间。

## 先看问题

同一个人可能同时学习 RAG、Agent 和数据分析。如果所有内容都写进同一份会话、图谱和复习表，会出现三个问题：

1. RAG 的对话会被 Agent 的复习扫描到。
2. 一张知识图谱混入多个目标，关系失去学习语境。
3. 学习档案无法说明某条证据属于哪个项目。

Whale CLI 的 WebUI 用“学习项目空间”解决这个问题。它不是模型设定，也不是 Git 分支；它是一份独立的本地学习数据目录。

## 使用方式

1. 打开 WebUI，点击左侧 `whale` 标志下方的当前学习项目。
2. 输入名称，例如“RAG 入门计划”，点击“创建并进入”。
3. 在新空间中开始对话、生成路线、建立图谱和复习表。
4. 随时从同一入口切换回另一个项目。

切换后，历史会话列表会立即变成该项目自己的列表；学习图谱、路线、间隔复习、学习档案、上传附件和 Datawhale BM25 语料也会跟着切换。

## 数据结构

假设当前工作目录为 `~/workspace/whale-cli`，新建的项目不会散落在用户目录，而是保存在工作目录下面：

```text
~/workspace/whale-cli/
└── .whale_cli/
    └── projects/
        ├── index.json
        └── project-rag-learning-a1b2c3/
            ├── project.json
            ├── sessions/
            ├── uploads/
            ├── datawhale_bm25_documents.jsonl
            └── .whale_cli/
                └── learning/
                    ├── state.json
                    ├── roadmaps/
                    ├── review-schedule.json
                    └── review-feedback.md
```

`project.json` 保存项目名称和创建时间；其余文件继续使用已有模块的 JSON/JSONL/Markdown 格式，因此可以备份、检查和迁移。

## 跨系统路径约定

学习项目空间同时支持 macOS、Linux 和 Windows。需要区分两类路径：

| 使用位置 | 统一规则 | Windows 例子 |
|---|---|---|
| 环境变量、终端命令、Obsidian 本地目录 | 使用当前系统的文件路径 | `$HOME\whale-workspace` |
| WebUI URL、Markdown 图片、Wiki 双链、图谱 JSON | 始终使用 `/` | `images/agent-loop.svg` |

后者是“逻辑路径”，不是让用户复制到 PowerShell 执行的本地路径。Whale 在 WebUI 边界会把 Windows 写法 `images\agent-loop.svg` 自动规范为 `images/agent-loop.svg`，所以同一份教程、知识图谱和附件索引能跨系统打开。

### 配置工作区

macOS / Linux：

```bash
export WHALE_HOME="$HOME/.whale"
export WHALE_WORKSPACE="$HOME/whale-workspace"
```

Windows PowerShell：

```powershell
$env:WHALE_HOME = "$HOME\.whale"
$env:WHALE_WORKSPACE = "$HOME\whale-workspace"
```

启动 `whale-web` 后，目录解析由 `pathlib` 完成，学习项目仍写入所选工作区的 `.whale_cli/projects/`。不要在 Markdown 中使用盘符绝对路径（例如 `C:\Users\...`）作为图片或图谱链接；将资源放进项目目录后使用相对逻辑路径即可。

## 默认学习空间为什么还在

升级前的数据可能已经存放在 `~/.whale/sessions/`、工作目录的 `.whale_cli/learning/` 或既有上传目录。Whale 不会在启动时自动移动它们。

所以界面中保留了“默认学习空间”：它是旧数据的兼容入口。新建的学习项目才使用上述隔离目录。确认旧数据无需再使用后，可以自行备份，再规划迁移；不要直接删除原目录。

## 模块如何配合

核心结构不是为每个页面复制一份状态，而是由 WebUI 在每个请求中解析当前项目，再建立同一份 `ProjectScope`：

```python
scope = ProjectScope(
    sessions=SessionStore(base_dir=project_root),
    attachments=AttachmentStore(project_root / "uploads"),
    learning_root=project_root,
    knowledge_base=DatawhaleKnowledgeBase(project_root / "datawhale_bm25_documents.jsonl"),
)
```

随后每个学习模块都从这个范围取得自己的存储位置：

| 模块 | 项目内数据 | 作用 |
|---|---|---|
| `SessionStore` | `sessions/` | 只恢复当前学习项目的对话 |
| `LearningStore` | `.whale_cli/learning/state.json` | 档案、知识节点、路线、复习和证据 |
| `ObsidianLearningWiki` | `learning-wiki/` | 生成当前项目的 Wiki 与双链页面 |
| `AttachmentStore` | `uploads/` | 防止其他项目通过附件 ID 读取文件 |
| `DatawhaleKnowledgeBase` | `datawhale_bm25_documents.jsonl` | 让资料检索依据随项目变化 |

模型任务也会收到这个根目录。`Soul(learning_workspace=...)` 会把学习工具、自动收录的 Wiki 对话和 `Agent` 内的 Datawhale 子代理指向选中的项目语料，而文件读写工具仍保持在原本的工作区策略内。

## 最小验证

在 WebUI 新建两个项目，例如“RAG 入门”和“Agent 实践”。在第一个项目发送：

```text
请记录“向量检索”这个知识点，并说明它与 RAG 的关系。
```

切换到第二个项目，打开“学习图谱”。图谱应为空，历史会话也不应出现“向量检索”。再切回第一个项目，应能看到原会话和该节点。

离线自动化验证：

```bash
./.venv/bin/python -m pytest tests/test_webui_settings.py -q
```

## 当前边界

- 学习项目隔离的是会话、学习状态、附件、Wiki 和项目语料，不会自动为每个项目创建 Git 仓库或修改现有代码工作区。
- API Key、模型设置仍是本机配置，因为它们是运行环境设置，不是学习内容。
- 当前提供创建与切换，不提供删除项目，避免误删长期学习记录。
- 默认学习空间是兼容层；旧数据的迁移需要先备份，并由用户确认后再做。
