# 第 3 章 · 读文件：Read

> 本章代码：`code/chapter-03/`。运行示例：`python ../code/chapter-03/main.py "读取 src/system-agent/setup-inference.ts 的前 200 行"`。本章把 `read_file` 从一行 `read_text()` 改造成支持行范围、行号、二进制检测和 PDF 提取的完整 Read 工具。

上一章结尾提到了一个问题：拿 `Path(path).read_text()` 去读一个近三千行的文件，整个文件全部进了上下文。程序没报错，模型甚至也可能给出正确答案——但后面每一轮调用都要继续携带这一万七千个 token，而模型真正需要看的可能只有四十行。

这一章要解决的就是这个问题：Read 返回什么、返回多少、用什么格式，直接影响模型后续每一轮的判断质量。

## 2. 先让模型只读一部分

最直接的办法，是给 Read 加一个固定上限：

```python
def read_file(path: str) -> str:
    lines = Path(path).read_text(encoding="utf-8").splitlines()
    return "\n".join(lines[:200])
```

现在一个三千行文件最多只返回前两百行。上下文不会再被整个文件占满。但如果 `detectSetupInference` 位于第 309 行，模型永远也看不到它。需要让模型在调用 Read 时自己指定范围：

```json
{
  “path”: “src/system-agent/setup-inference.ts”,
  “start_line”: 309,
  “end_line”: 360
}
```

修改函数：

```python
from pathlib import Path


DEFAULT_WINDOW_LINES = 200


def read_file(
    path: str,
    start_line: int = 1,
    end_line: int | None = None,
) -> str:
    text = Path(path).read_text(encoding="utf-8")
    lines = text.splitlines()
    total = len(lines)

    start = max(1, start_line)

    if end_line is None:
        end = min(
            total,
            start + DEFAULT_WINDOW_LINES - 1,
        )
    else:
        end = min(total, end_line)

    selected = lines[start - 1:end]
    return "\n".join(selected)
```

默认仍然最多读取 200 行。模型知道目标位置时，可以直接指定范围；暂时不知道时，也可以先读一部分，再根据返回内容继续调整：

先看一部分，从结果中获得新线索，判断下一次应该看哪里，再调用 Read。

Read 不需要一次把整份文件交给模型。它只需要支持模型逐步探索。`ReadFileTool` 的 schema 也要同步更新：

```python
class ReadFileTool(Tool):
    name = "read_file"
    description = (
        "读取文本文件。可用 start_line 和 end_line "
        "指定读取范围；读取大文件时应优先分段读取。"
    )
    schema = {
        "type": "function",
        "function": {
            "name": "read_file",
            "description": "...",
            "parameters": {
                "type": "object",
                "properties": {
                    "path": {
                        "type": "string",
                        "description": "要读取的文件路径",
                    },
                    "start_line": {
                        "type": "integer",
                        "description": "开始行，默认是第 1 行",
                    },
                    "end_line": {
                        "type": "integer",
                        "description": (
                            "结束行；省略时最多读取 200 行"
                        ),
                    },
                },
                "required": ["path"],
            },
        },
    }
```

如果只升级 `__call__` 却没有修改 schema，模型不会知道 `start_line` 和 `end_line` 这两个参数存在。schema 和执行逻辑在同一个类里，改起来不容易漏。

其他 Coding Agent 的 Read 工具默认窗口各不相同：

## 3. 只返回代码还不够

现在 Read 能返回指定范围了。让模型读取：

```text
src/system-agent/setup-inference.ts 的第 309 到 360 行。
```

工具返回：

```typescript
export async function detectSetupInference(
  deps: DetectSetupInferenceDeps = {},
): Promise<SetupInferenceDetection> {
  const { readConfigFileSnapshot } = await import(“../config/config.js”);
  const snapshot = await readConfigFileSnapshot();
  if (snapshot.exists && !snapshot.valid) {
    throw new Error(invalidSetupConfigError(snapshot));
  }
```

模型看懂了代码。接下来，它准备修改其中的 `throw new Error`。但这个文件里可能还有多个完全相同的：

```typescript
throw new Error(...)
```

如果模型只说”修改 `throw new Error`”，后面的 Edit 很难知道它指的是哪一个。Read 的返回结果需要告诉模型，这段代码位于哪里：

```text
 309  export async function detectSetupInference(
 310    deps: DetectSetupInferenceDeps = {},
 311  ): Promise<SetupInferenceDetection> {
 312    const { readConfigFileSnapshot } = await import(“../config/config.js”);
 313    const snapshot = await readConfigFileSnapshot();
 314    if (snapshot.exists && !snapshot.valid) {
 315      throw new Error(invalidSetupConfigError(snapshot));
 316    }
```

模型知道当前关注的是第 315 行附近，也能使用周围代码构造更准确的修改范围：

```typescript
if (snapshot.exists && !snapshot.valid) {
    throw new Error(invalidSetupConfigError(snapshot));
}
```

而不是只拿一个到处都会出现的 `throw new Error`。加入行号：

```python
numbered = "\n".join(
    f"{line_no:>5}  {line}"
    for line_no, line in enumerate(
        selected,
        start=start,
    )
)
```

但只有行号仍然不够，模型还应该知道：

* 这是哪个文件；
* 文件总共有多少行；
* 当前看到的是哪一段；
* 后面是否还有内容。

因此在结果前面加一个 header：

```python
header = (
    f"# {path} "
    f"({total} lines, showing {start}-{end})"
)
```

如果后面还有未读取内容，再加一句提示：

```python
if end < total:
    continuation = (
        f"# More: {total - end} lines remain. "
        f"Continue with start_line={end + 1}."
    )
```

## 4. 只限制行数还不够

我们已经规定：一次最多返回 200 行。对于普通源代码，这个限制通常有效。

现在读取一个压缩后的 JavaScript 文件：

```text
dist/app.min.js
```

它可能只有一行，但这一行有一百多万个字符。Read 完全遵守了”最多返回 200 行”的限制，却仍然把整个文件塞进上下文。类似的情况还有：

* 没有换行的超大 JSON；
* 一整行 Base64 数据；
* 压缩后的 CSS；
* 自动生成的 Source Map；
* 某些极长的日志记录。

行数只是估算内容大小的一种近似。大多数源代码一行不会特别长，所以通常有效；遇到压缩格式时就失灵了。给每一行增加长度限制：

```python
MAX_LINE_CHARS = 2000


def truncate_line(line: str) -> tuple[str, bool]:
    if len(line) <= MAX_LINE_CHARS:
        return line, False

    shortened = (
        line[:MAX_LINE_CHARS]
        + f" ... <truncated, original {len(line)} chars>"
    )
    return shortened, True
```

格式化时记录哪些行被截断：

```python
formatted = []
truncated_lines = []

for line_no, line in enumerate(
    selected,
    start=start,
):
    safe_line, was_truncated = truncate_line(line)

    if was_truncated:
        truncated_lines.append(line_no)

    formatted.append(
        f"{line_no:>5}  {safe_line}"
    )
```

如果发生截断，要明确告诉模型：

```text
# Note: long lines were truncated: 1
```

截断后必须在返回结果里标注，否则模型会把残缺内容当成完整代码。更严格的做法是同时限制总字符数：

```python
MAX_RESULT_CHARS = 30_000
```

达到上限时停止返回，并告诉模型从哪一行继续。

## 5. 让 Read 读一张 PNG 会发生什么

再试一个完全不同的文件：

```text
> 读一下 assets/logo.png。
```

当前工具执行：

```python
Path("assets/logo.png").read_text(
    encoding="utf-8"
)
```

得到：

```text
UnicodeDecodeError:
'utf-8' codec can't decode byte 0x89 in position 0
```

如果把这段异常直接返回给模型，它只知道”UTF-8 解码失败”。它可能猜测文件用了其他文本编码，下一轮又尝试 GBK、Latin-1 或其他方案。但问题根本不在编码，`logo.png` 不是文本文件。Read 应该在读取之前先判断文件类型。

最简单的判断方式是扩展名：

```python
IMAGE_EXTENSIONS = {
    ".png",
    ".jpg",
    ".jpeg",
    ".gif",
    ".webp",
    ".bmp",
    ".ico",
}

ARCHIVE_EXTENSIONS = {
    ".zip",
    ".tar",
    ".gz",
    ".7z",
}

OFFICE_EXTENSIONS = {
    ".docx",
    ".pptx",
    ".xlsx",
}
```

但扩展名并不完全可靠。文件可能没有扩展名，也可能被错误地改名。因此还可以读取文件开头的一小段字节。很多文件格式有固定的开头：

```python
MAGIC_BYTES = {
    b"\x89PNG": "PNG image",
    b"\xff\xd8\xff": "JPEG image",
    b"%PDF": "PDF document",
    b"PK\x03\x04": "ZIP container",
}
```

这些固定开头通常被称为文件签名或 magic bytes。

```python
def detect_file_kind(path: Path) -> str:
    suffix = path.suffix.lower()

    if suffix in IMAGE_EXTENSIONS:
        return "image"

    if suffix == ".pdf":
        return "pdf"

    if suffix in OFFICE_EXTENSIONS:
        return "office"

    if suffix in ARCHIVE_EXTENSIONS:
        return "archive"

    head = path.read_bytes()[:16]

    if head.startswith(b"\x89PNG"):
        return "image"

    if head.startswith(b"\xff\xd8\xff"):
        return "image"

    if head.startswith(b"%PDF"):
        return "pdf"

    if b"\x00" in head:
        return "binary"

    return "text"
```

现在读取图片时，不再返回底层 Python 异常：

```text
Error: 检测到 PNG 图片。
当前 read_file 只返回文本内容，
继续尝试其他文本编码没有意义。
```

返回里包含三层信息：文件是什么格式、为什么当前方式不能读取、下一步不应该继续尝试什么。

## 6. 不同文件不能用同一种办法读

Claude Code、Codex 这类 Coding Agent 看上去”什么文件都能读”。

源代码、Markdown、PDF、图片、Notebook、Office 文档，在一些环境里都可以处理。但它们并非全部经过：

```python
Path(path).read_text()
```

模型看到的可能仍然是一个 Read 工具，但程序内部会根据文件类型选择不同的处理方式：

```text
Read(path)
    │
    ├── .py / .md / .json
    │      └── 文本读取
    │          + 行范围
    │          + 行号
    │          + 字符限制
    │
    ├── .pdf
    │      └── 提取 PDF 文本层
    │          + 按页读取
    │          + 扫描页提示
    │
    ├── .png / .jpg
    │      └── 作为图片交给多模态模型
    │
    ├── .ipynb
    │      └── 解析 JSON
    │          + 按 Cell 返回
    │
    └── .docx / .pptx
           └── 解析文档结构
               + 文字
               + 图片
               + 版面信息
```

对模型来说，”读取文件”的意思是”我想理解这个文件的内容”。至于用 `read_text()` 还是 PDF 解析器，是程序内部的事。Read 在这里充当入口，先识别文件，再选择合适的 Reader。

文本之外，PDF 是最常遇到的格式。

## 7. PDF 也能读

如果只按照”文本 / 二进制”分类，PDF 应该直接被拦截。它确实不是普通 UTF-8 文本，但很多 PDF 内部带有可提取的文字层。标题、段落、页码和部分表格内容，都可以通过 PDF 解析器取出来。PNG 里面是像素数据，提取文字没有意义。PDF 虽然也是二进制，但内部可能保存着模型能理解的文本。

最小实现可以使用 PyMuPDF：

```python
def read_pdf(
    path: Path,
    start_page: int = 1,
    end_page: int | None = None,
) -> str:
    try:
        import fitz
    except ImportError:
        return (
            "Error: 读取 PDF 需要安装 pymupdf。"
            "运行：uv pip install pymupdf"
        )

    document = fitz.open(path)
    total_pages = len(document)

    start = max(1, start_page)

    if end_page is None:
        end = min(
            total_pages,
            start + 4,
        )
    else:
        end = min(total_pages, end_page)

    output = [
        f"# {path} "
        f"({total_pages} pages, showing {start}-{end})"
    ]

    for page_no in range(start, end + 1):
        page = document[page_no - 1]
        text = page.get_text("text").strip()

        output.append(
            f"\n--- Page {page_no} ---"
        )

        if text:
            output.append(text)
        else:
            output.append(
                "[No extractable text on this page]"
            )

    document.close()
    return "\n".join(output)
```

PDF 也不能默认一次读完。一份 200 页的文档全部进入上下文，与一次读取三千行源代码没有本质区别。

文本文件使用：

```text
start_line / end_line
```

PDF 使用：

```text
start_page / end_page
```

两个接口背后是同一种设计：由模型决定这一轮的读取范围。

如果某一页没有提取出文字，工具也不应该直接回答”页面为空”。它可能是一份扫描 PDF，页面里只有图片。可以明确返回：

```text
第 7 页没有可提取文字，
可能是一张扫描页面，需要 OCR 或图片读取能力。
```

模型收到这条信息后不会继续在同一条路上重试。

## 8. 报错以后，模型该怎么办

回头看 Read 可能遇到的错误：

- 文件不存在
- 路径是目录
- 读取范围超出文件长度
- 结束行小于开始行
- 文件不是 UTF-8 文本
- 文件是图片
- PDF 页面没有文本层
- 文件内容过长

最省事的做法，是把 Python 的原始异常直接返回。但原始异常通常只描述程序在哪里失败：

```text
UnicodeDecodeError
FileNotFoundError
TypeError
IndexError
```

模型需要的是下一步该怎么办。例如文件不存在，只有：

```text
Error: FileNotFoundError
```

模型不知道路径写错在哪里。更好的结果是：

```text
Error: 文件不存在：src/system-agent/setup-inferenc.ts。
请确认路径；如果不知道准确路径，
先使用目录或搜索工具寻找候选文件。
```

读取范围超出：

```text
Error: start_line=4000 超出文件范围。
文件共有 2897 行。
```

文件太大：

```text
Error: 文件共有 2897 行，
本次最多返回 200 行。
请使用 start_line 和 end_line 分段读取。
```

图片文件：

```text
Error: 检测到 PNG 图片。
继续尝试文本编码没有意义，
需要图片读取能力。
```

PDF 没有文字层：

```text
第 7 页没有可提取文字，
可能是扫描页面，需要 OCR。
```

每条返回都给出了具体的下一步线索，而不是一个光秃秃的异常名。

但消息内容只是一半。回头看上一章的代码：工具读取成功，返回一段文本；读取失败，也返回一段文本。main.py 拿到返回值以后，没法不看内容就知道这次调用是成功还是失败。终端输出也没法区分——绿色表示成功、红色表示错误——因为程序根本不知道结果是哪一种。

换一个结构就行了。让工具返回一个 dict，带上 exit_code：

```python
# registry.py（新增）

def ok(stdout: str = "") -> dict:
    return {"stdout": stdout, "stderr": "", "exit_code": 0}


def err(stderr: str) -> dict:
    return {"stdout": "", "stderr": stderr, "exit_code": 1}
```

工具成功时调 `ok(content)`，失败时调 `err(message)`。main.py 检查 `exit_code`，0 是成功、非 0 是失败——和 shell 命令的退出码一个道理。这两个函数加在 `registry.py` 里，和 Tool 基类放在一起。从本章开始，所有工具的 `__call__` 返回 `dict` 而不是 `str`。

## 9. 把文本 Read 放在一起

先把文本文件做好，同时保留 PDF 和其他类型的分流提示。

```python
# tools.py（ReadFileTool）

from pathlib import Path

from registry import Tool, ok, err


DEFAULT_WINDOW_LINES = 200
MAX_LINE_CHARS = 2000

IMAGE_EXTENSIONS = {
    ".png",
    ".jpg",
    ".jpeg",
    ".gif",
    ".webp",
    ".bmp",
    ".ico",
}

ARCHIVE_EXTENSIONS = {
    ".zip",
    ".tar",
    ".gz",
    ".7z",
}

OFFICE_EXTENSIONS = {
    ".docx",
    ".pptx",
    ".xlsx",
}


def detect_file_kind(path: Path) -> str:
    suffix = path.suffix.lower()

    if suffix in IMAGE_EXTENSIONS:
        return "image"

    if suffix == ".pdf":
        return "pdf"

    if suffix in OFFICE_EXTENSIONS:
        return "office"

    if suffix in ARCHIVE_EXTENSIONS:
        return "archive"

    head = path.read_bytes()[:16]

    if head.startswith(b"\x89PNG"):
        return "image"

    if head.startswith(b"\xff\xd8\xff"):
        return "image"

    if head.startswith(b"%PDF"):
        return "pdf"

    if b"\x00" in head:
        return "binary"

    return "text"


def truncate_line(line: str) -> tuple[str, bool]:
    if len(line) <= MAX_LINE_CHARS:
        return line, False

    shortened = (
        line[:MAX_LINE_CHARS]
        + f" ... <truncated, original {len(line)} chars>"
    )
    return shortened, True


class ReadFileTool(Tool):
    name = "read_file"
    description = (
        "读取当前项目中的文本文件，返回带行号的内容。"
        "可用 start_line 和 end_line 指定读取范围。"
        "读取大文件时应优先分段读取，不要一次请求全文。"
    )
    schema = {
        "type": "function",
        "function": {
            "name": "read_file",
            "description": (
                "读取当前项目中的文本文件，返回带行号的内容。"
                "可用 start_line 和 end_line 指定读取范围。"
                "读取大文件时应优先分段读取，不要一次请求全文。"
            ),
            "parameters": {
                "type": "object",
                "properties": {
                    "path": {
                        "type": "string",
                        "description": "要读取的文件路径",
                    },
                    "start_line": {
                        "type": "integer",
                        "description": "起始行，默认是第 1 行",
                    },
                    "end_line": {
                        "type": "integer",
                        "description": (
                            "结束行；省略时最多读取 200 行"
                        ),
                    },
                },
                "required": ["path"],
            },
        },
    }

    def __call__(
        self,
        *,
        path: str,
        start_line: int = 1,
        end_line: int | None = None,
    ) -> dict:
        file_path = Path(path)

        if not file_path.exists():
            return err(f"Error: 文件不存在 {path}")

        if not file_path.is_file():
            return err(f"Error: 不是文件 {path}")

        kind = detect_file_kind(file_path)

        if kind == "image":
            return err(
                f"Error: 检测到图片文件 {path}，"
                "read_file 只返回文本内容。"
            )

        if kind == "pdf":
            return err(f"Error: 检测到 PDF {path}，需要文档解析器。")

        if kind == "office":
            return err(f"Error: 检测到 Office 文档 {path}，需要文档解析器。")

        if kind in {"archive", "binary"}:
            return err(f"Error: {path} 看起来是二进制文件，拒绝读取。")

        try:
            text = file_path.read_text(encoding="utf-8")
        except UnicodeDecodeError:
            return err(f"Error: {path} 不是有效的 UTF-8 文本")

        lines = text.splitlines()
        total = len(lines)

        if total == 0:
            return ok(f"# {path} (empty file)")

        start = max(1, start_line)

        if start > total:
            return err(
                f"Error: start_line={start} 超出文件范围，"
                f"文件共有 {total} 行。"
            )

        if end_line is None:
            end = min(total, start + DEFAULT_WINDOW_LINES - 1)
        else:
            end = min(total, end_line)

        if end < start:
            return err(f"Error: end_line={end} 小于 start_line={start}")

        selected = lines[start - 1:end]
        output = [f"# {path} ({total} lines, showing {start}-{end})"]
        truncated_lines = []

        for line_no, line in enumerate(selected, start=start):
            safe_line, was_truncated = truncate_line(line)
            if was_truncated:
                truncated_lines.append(line_no)
            output.append(f"{line_no:>5}  {safe_line}")

        if end < total:
            output.append(
                f"\n# More: {total - end} lines remain. "
                f"Continue with start_line={end + 1}."
            )

        if truncated_lines:
            values = ", ".join(str(n) for n in truncated_lines)
            output.append(f"\n# Note: long lines truncated: {values}")

        return ok("\n".join(output))
```

真正执行文本读取的部分仍然不复杂。大部分代码在处理边界情况：路径是否存在、目标是不是文件、它属于什么文件类型、本次应该返回哪一段、单行是否过长、结果是否完整、失败后模型应该怎样继续。

## 11. 回头看这个 Read

最初的 Read 只有 `Path(path).read_text()`，只关心文件能不能读取。改造后的 Read 多了很多判断：这次应该读取多少、模型怎样知道内容的位置、返回是否完整、文件应该使用哪种读取方式、失败后模型应该怎样继续。这些问题在后面的工具中也会反复出现，这里集中列出来：

程序成功不等于工具有用。一次返回三千行代码，程序层面没有报错，但 Agent 任务可能因为上下文被淹没而变差。`start_line`、`end_line`、PDF 页码这些参数都在做同一件事：给模型一个可控的观察窗口，逐步获取信息。

返回结果要带坐标（文件路径、行号、总行数、当前范围和剩余内容），让模型知道自己看了哪里、还有多少没看。如果发生了截断，也必须标注，否则模型会把局部信息当成完整事实。

模型调用的始终是 `read_file`，程序内部可以针对文本、PDF、图片走不同路径。裸露的 Python 异常只说明程序在哪里失败，好的工具错误还会告诉模型为什么失败、接下来可以怎样调整。
