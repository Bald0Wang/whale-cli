Edit 失败后，模型怎样自我修正

点击"下一步"逐步推进，观察错误信息的质量如何决定修正效率

1
模型发起 Edit
⏺ edit_file({ path: "src/tools/execution.ts", old_string: "return `core.${ref.executorId}`;", new_string: "return `core/${ref.executorId}`;" })
2
匹配失败 — 错误信息带了真实内容
✗ old_string not found in execution.ts 最接近的匹配（第 8 行）: 7 │ case "core": 8 │ return `core:${ref.executorId}`; 9 │ case "plugin": 你给的: core.${ref.executorId} ← 用了点号 实际是: core:${ref.executorId} ← 实际是冒号
3
模型看到了正确内容
模型的判断： "我记成了 core.，但实际分隔符是 core:。 用文件里真正的内容作为 old_string 重试。"
4
第二次 Edit — 成功
⏺ edit_file({ old_string: "return `core:${ref.executorId}`;", new_string: "return `core/${ref.executorId}`;" }) ✓ Applied edit to execution.ts
关键不在重试次数，在错误信息的质量。如果只返回 "Error: not found"，模型会盲目换写法重试。但我们的实现把文件中最接近的代码也返回了——模型一看就知道自己把 : 记成了 .，一次修正就对了。
