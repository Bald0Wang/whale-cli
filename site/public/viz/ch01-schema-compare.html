Schema Description 质量对比实验

差的 schema
{ "name": "read_file", "description": "读文件", "parameters": { "properties": { "path": { "type": "string" } }, "required": ["path"] } }
User
看看 src/auth 目录下的登录代码
Model
read_file({path: "src/auth"})
Result
Error: EISDIR - "src/auth" is a directory, not a file
Model
schema 没说不能传目录，模型只看到 "读文件" + path: string，猜测路径即可，结果传了目录。
好的 schema
{ "name": "read_file", "description": "读取一个本地文本文件的内容并返回字符串。传入文件路径（不是目录）。支持 start_line/end_line 只读一段。", "parameters": { "properties": { "path": { "type": "string", "description": "文件路径，必须是文件不是目录" }, "start_line": { "type": "integer", "description": "起始行号" }, "end_line": { "type": "integer", "description": "结束行号" } }, "required": ["path"] } }
User
看看 src/auth 目录下的登录代码
Model
glob({pattern: "src/auth/*.ts"})
Result
["src/auth/login.ts", "src/auth/logout.ts", "src/auth/middleware.ts"]
Model
read_file({path: "src/auth/login.ts", start_line: 1, end_line: 30})
Result
Success - 返回 login.ts 前 30 行内容
关键洞察
schema 的 description 是写给模型看的。模型靠这几句话决定什么时候调你的工具、传什么参数。写得好，模型一次就调对；写得差，可能传错参数或者根本不调。
#1 工具描述
description 只写 "读文件"
详细说明用途、输入限制、支持的功能
#2 参数描述
参数没有 description，模型靠猜
每个参数都有 description，明确约束
#3 参数丰富度
只有一个 path，模型没有精确控制的选项
提供 start_line / end_line，模型能精确读取
