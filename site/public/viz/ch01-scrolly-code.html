Agent Loop：20 行代码做了什么

Whale CLI 的主循环。往下滚动，右边的代码会跟着高亮对应的部分。

第 1 步

接收用户输入

用户在终端里输入一句话，程序把它包成 {"role": "user", "content": "..."} 塞进 messages 列表。这是整个循环的起点。

messages 列表从这里开始增长，到 session 结束时可能有上百条。Ch09 讲怎么分层管理它们。
第 2 步

发给模型

把 messages 和工具 schema 一起发给模型。API 是无状态的，每次都要带完整历史。tools_schema 告诉模型有哪些工具可用。

你在 Claude Code 里每发一条消息，背后都是把完整对话历史重新发一遍。Prompt Cache 能省掉重复部分的计算费用。
第 3 步

追加 assistant 响应

模型返回的响应立刻追加到 messages 里。必须先 append 再处理工具调用，因为 API 协议要求 tool message 紧跟在对应的 assistant message 后面。

这一步的顺序搞反了（先处理工具再 append），API 会返回 400 错误。Ch01 §5.4 专门讲了这个坑。
第 4 步

检查：要不要调工具？

如果模型没有返回 tool_calls，说明它觉得任务完成了，直接打印回答退出循环。如果有 tool_calls，进入下一步执行工具。

这是 ReAct 循环里的"判断点"——模型每一轮要么 Reason（输出文本），要么 Act（调用工具）。
第 5 步

解析工具调用

从 tool_calls 里取出工具名和参数。注意 arguments 是 JSON 字符串不是 dict，要 json.loads 解析一下。

我们翻了 6 个项目，每一个都有这一步 json.loads。OpenAI 选择传字符串而不是嵌套对象，是为了避免 HTTP JSON 双重转义的问题。
第 6 步

执行工具

run_tool 按名字找到对应函数执行。Ch02 的 registry 让这一步变成查字典——加新工具不用改主循环。

工具执行是本地的（读文件、跑命令），不走 API。执行时间从几毫秒（read_file）到几分钟（npm install）不等。
第 7 步

结果回灌 messages

工具执行结果以 role: "tool" 塞回 messages，带上 tool_call_id 对应上面的调用。然后循环回到第 2 步，把更新后的 messages 再发给模型。

这就是"循环"的含义——模型看到工具结果后决定下一步：继续调工具还是给出最终回答。一个复杂任务可能循环 20-30 次。
