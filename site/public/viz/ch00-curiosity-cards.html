Coding Agent 的 6 个日常现象

点击展开看原理

01
它为什么先搜再改，不直接改？ ▾
你说"把 clearCookie 加个 path 参数"，它先 Glob 扫文件，再 Grep 搜关键词，找到了才去 Edit。
Globsrc/**/*.ts → 47 files
↓
Grep"clearCookie" → 3 matches in 2 files
↓
Readlogout.ts lines 40-60
↓
EditclearCookie("session") → clearCookie("session", {path:"/"})
Ch05 Ch04 模型不知道代码在哪个文件。它从 tool schema 里看到有 Glob 和 Grep，自己决定先缩小范围再动手。这条 glob → grep → read → edit 链不是硬编码的，是模型根据 description 自己选的。
02
改错了它怎么自己修好的？ ▾
Edit 失败冒出红字，模型停了一拍，重新 Read 了文件，换了写法再试，成功了。
Editold: result = data * 2
✗ not found — 实际第47行: result = transform(data)
💭 模型看到了正确内容，重新构造 old_string
Editold: result = transform(data) ✓
Ch04 关键在错误信息的质量。我们不返回干巴巴的 "not found"，而是把实际文件内容一起返回。模型看到"你写的是 data * 2，实际是 transform(data)"，一次就能改对。
03
复杂任务它为什么先列计划？ ▾
你说"把日志从 print 换成 logging"，它第一件事是列了个 4 步计划，每做完一步回来打勾。
[>] Grep 搜索所有 print() 调用
[ ] 替换为 logging 调用
[ ] 加 import logging
[ ] 跑测试确认通过
(0/4 completed)
Ch07 没有 todo 的模型在长任务里容易丢步骤——原始计划被工具返回值往后推，注意力分散了。TodoWrite 每隔几轮把完整计划刷新回 context，模型随时知道自己做到哪了。
04
聊了 20 轮之后它怎么还没撑爆？ ▾
30 多轮重构任务，读了十几个文件、改了 5 个、跑了 3 次测试。按理说 context 早满了。
System
Tools
Workspace
Todo
History
Current
Ch09 Ch10 Prompt 按变化速率分 6 层。前两层（system + tools）从不变，API 可以缓存。History 涨得最快，快满了用 /compact 让模型把老对话压缩成摘要——从 85K token 压到 8K。
05
它跑 rm -rf 之前为什么会先问你？ ▾
跑 ls、pytest 不会问，但 rm 和 git push --force 会弹确认框。
pytest tests/ -v→ 自动执行 ✓
rm old_tests.py→ ⚠️ 确认执行？[y/n]
rm -rf /→ 🚫 拦截
Ch06 Ch10 三档处理：只读操作自动放行，写操作弹确认，高危命令直接拦。Claude Code 内部有 23 种安全检查，我们从正则黑名单 + 二档 approval 开始做。
06
它怎么知道这是个 Python 项目？ ▾
你说"跑一下测试"，它直接 pytest。没告诉它用什么，但它就是知道。
cwd: /home/user/my-project
git: feature/auth (3 files changed)
stack: Python 3.11 + pytest + FastAPI
AGENTS.md: "测试用 pytest tests/ -x"
→ 全部塞进 system prompt，模型从第一轮就知道
Ch08 启动时自动收集：当前目录、git 分支、最近 commit、README、配置文件、AGENTS.md。这些塞进 prompt 后，模型第一轮就知道该用 pytest 而不是 npm test。没有这些，它每次都要先花几步自己去摸索。
